# КОНТРАКТ РАБОТЫ: ДВА ЭТАПА, ДВА ТЗ

> **Главное правило.** Это ТЗ разбито на **два независимых захода** визуального агента. **Не пытайся сделать всё за раз.** Каждый этап сдаётся отдельно и согласуется отдельно.

## Этап 1. Универсальный каркас (плейсхолдеры)

**Что входит:** Части 0, 1, 2, 3, 4, 6, 7, 8, 9 этого ТЗ (всё, кроме Части 5).

**Что агент делает:**
1. Берёт исходный `v5.0 — Проценты, пропорции, масштаб — reader.html` (финальный, текст зафиксирован).
2. Создаёт `v5.0 — Проценты, пропорции, масштаб — reader-sketchbook.html`.
3. Применяет CSS-контракт из Части 2 ко всем 58 секциям.
4. Расставляет **плейсхолдеры картинок** в нужных местах:
   ```html
   <figure class="sketch">
     <div class="placeholder" data-image="metricheskiy-most.png"
          data-slide="7" style="width:100%;aspect-ratio:4/3;
          background:#E8DFD0;border:1px dashed #6E554F;
          display:flex;align-items:center;justify-content:center;
          color:#6E554F;font-size:14px;">
       [картинка: metricheskiy-most.png, слайд 7]
     </div>
   </figure>
   ```
5. Возвращает Olga файл на проверку. **Сам картинки не ищет и не вставляет.**

**Что Olga проверяет:**
- Layout (обтекание, шрифты, цвета, отступы).
- Адаптивность на 1100 / 900 / 600 / 400 px.
- Плашки — правильные цвета и типы.
- TOC, scroll-spy, кнопка «Наверх».
- Тёмный фон мини-тестов, свёрнутые ответы.

**Если Olga говорит «каркас ок»** → переходим к Этапу 2.

## Этап 2. Вставка картинок по реестру

**Что входит:** Часть 5 этого ТЗ (Реестр картинок) + Часть 2.5 (Качество картинок).

**Что агент делает:**
1. Берёт `reader-sketchbook.html`, одобренный Olga после Этапа 1.
2. По списку из Части 5 берёт файл из `assets/` и заменяет плейсхолдер на:
   ```html
   <figure class="sketch">
     <img src="assets/metricheskiy-most.png" alt="Метрический мост"
          style="width:100%;height:auto;">
     <figcaption>Метрический мост между шкалами</figcaption>
   </figure>
   ```
3. Возвращает финальный файл на проверку.

**Что Olga проверяет:**
- Картинки на нужных слайдах.
- Подписи под картинками (кратко, не дублируют текст).
- Качество картинок на retina display.
- Никаких висящих плейсхолдеров.

## Почему два этапа, а не один

- **Картинки — это переменная часть.** Картинки можно менять, перерисовывать, добавлять новые. Каркас — нет.
- **Плейсхолдеры дают чистый пилот.** Можно проверить вёрстку, не дожидаясь готовности всех иллюстраций.
- **Разделение ошибок.** Если сломан layout — это Этап 1. Если картинка не та или плохого качества — это Этап 2. Не надо переделывать всё.
- **Параллельная работа.** Пока визуальный агент делает Этап 1, Olga может доделывать/перерисовывать картинки для Этапа 2.

## Если агент игнорирует двухэтапность

Если визуальный агент вставит картинки на Этапе 1 или сделает всё за один проход — это ошибка. Olga вправе вернуть файл на доработку.

# ЧАСТЬ 0: НЕЙРОБИОЛОГИЧЕСКОЕ ОБОСНОВАНИЕ

> **Зачем эта часть.** Каждое визуальное решение в ТЗ опирается на принципы когнитивной нейробиологии и теорию мультимедийного обучения (Mayer, 2009–2021). Визуальный агент должен понимать **почему**, чтобы не «улучшать» дизайн в сторону, которая ломает обучение.

## 0.1. Три архитектурных ограничения мозга

Опираемся на три фундаментальных факта, которые нельзя игнорировать при вёрстке учебника:

| Факт | Источник | Следствие для вёрстки |
|---|---|---|
| **Рабочая память — 4 ± 1 элемента** | Miller (1956), Cowan (2001) | Один слайд = одна мысль. Сложные слайды разбиты (14a/14b). Мини-тест = 2 задачи, не 5. |
| **Картинка превосходит текст** (Picture Superiority Effect) | Paivio (1971), Standing (1973) | Ключевые понятия (мост, перевёртыш, атлас, переливание) — всегда с рисунком слева. |
| **Лишнее перегружает** (Coherence principle) | Mayer (2009) | Никаких украшений, фоновых паттернов, эмодзи, теней-переливов. Только бумага, чернила, иллюстрация. |

## 0.2. Семь принципов мультимедийного обучения (Mayer)

Эти принципы — фундамент. Каждому решению в Частях 1–8 соответствует один или несколько принципов.

### 1. Spatial Contiguity (пространственная смежность)
**Принцип:** люди учатся лучше, когда текст и картинка расположены рядом на экране, а не раздельно.
**Реализация:** горизонтальный слайд — картинка слева, текст справа, в одном окне без скролла. Gap 36px — достаточно близко, чтобы взгляд не терял связь.

### 2. Temporal Contiguity (временная смежность)
**Принцип:** связанная информация появляется одновременно.
**Реализация:** подпись к картинке — сразу под ней, не внизу страницы. Таблица переменных — рядом с формулой, не в шпаргалке через 5 слайдов.

### 3. Segmenting (сегментация)
**Принцип:** контент разбит на сегменты, ученик управляет темпом.
**Реализация:** каждый слайд = один смысловой шаг. Оглавление слева (TOC) позволяет перейти к любому разделу. Скролл = пауза. Никаких автопроигрываний.

### 4. Signaling (сигнализация)
**Принцип:** ключевые элементы выделены визуально, чтобы направить внимание.
**Реализация:** **три типа плашек разного цвета** (ловушка — терракот, правило — горчица, памятка — мята). Заголовки блоков в верхнем регистре. Нумерация слайдов жирная. Дискриминатор в шпаргалках выделен рамкой.

### 5. Modality (модальность)
**Принцип:** слова лучше воспринимаются на слух, чем как текст на экране.
**Контекст:** мы — текстовый учебник, поэтому компенсируем **ритмом абзацев** (один абзац = одна мысль, 2–4 строки), **воздухом** (line-height 1.7) и **визуальными якорями** (картинка рядом с каждым новым термином). Эта компенсация записана в Части 3.

### 6. Coherence (когерентность)
**Принцип:** люди учатся лучше, когда лишний материал исключён.
**Реализация:** ни одного эмодзи-иконки, ни одной тени-перелива, ни одного фонового паттерна. Только бумага, чернила, иллюстрация. Стикеры-плашки НЕ добавляются автоматом (Olga расставит их сама после вёрстки).

### 7. Personalization (персонализация)
**Принцип:** неформальный тон увеличивает вовлечённость.
**Реализация:** обращение на «ты» в тексте, мягкий тон плашек (не «ОШИБКА!», а «Ловушка»). Цвет терракота вместо агрессивно-красного.

### 8. Redundancy (отсутствие избыточности)
**Принцип:** не дублировать одну и ту же информацию в нескольких форматах одновременно.
**Реализация:** формула даётся в виде KaTeX, **не дублируется** текстом рядом. Пояснение — отдельно от формулы. Картинка не подписывается тем же, что уже сказано в тексте.

### 9. Picture Superiority (превосходство картинки)
**Принцип:** картинки запоминаются лучше слов (конкретные образы > абстрактные описания).
**Реализация:** каждое ключевое понятие имеет визуальный якорь. «Метрический мост» — это не абстрактное правило, а нарисованный мостик между шкалами. «Зависимости» — четыре стрелки на одной картинке. Ученик запомнит картинку, а по ней восстановит правило.

## 0.3. Рабочая память и chunking

**Правило 4 ± 1 (Miller/Cowan):** рабочая память удерживает 4 ± 1 элемента одновременно.

**Как реализовано:**
- Один слайд = одна микро-тема (1 элемент).
- Мини-тест = **ровно 2 задачи** (не 5, не 3).
- Сложный слайд разбит: Слайд 14 → 14a (теория, мотивация) + 14b (формула, переменные, ловушка).
- Мини-тесты появляются **каждые 5–10 слайдов** (spaced repetition) — после Блоков 2, 3, 5, 6, 7, 8.
- Мостики (паспорт темы + анонс) дают **паузу для отдыха** между блоками, не новую информацию.

## 0.4. Эмоциональная безопасность (Affiliative tone)

**Факт:** тревожность снижает эффективность обучения (Eysenck, Calvo, 1992). Тёплые тона и мягкие цвета снижают кортизол.

**Реализация:**
- Кремовый фон `#F5F2EB` — тёплый, не агрессивно-белый.
- Терракот `#D97443` для ловушек — мягче, чем `#FF0000`.
- Мята `#618B8B` для правильных ответов — не кричаще-зелёная.
- Тон плашек: «Ловушка» (не «Ошибка!»), «Правило» (не «ЗАПОМНИ!»), «Памятка» (не «ФОРМУЛА!»).

## 0.5. Гештальт-принципы (композиция страницы)

| Принцип | Что делает | Реализация |
|---|---|---|
| Близость | Элементы рядом воспринимаются как группа | Gap между рисунком и текстом 36px < gap между слайдами 24px+padding |
| Сходство | Одинаковые элементы = одна категория | Все 3 типа плашек визуально однородны по форме (скруглённые углы), различаются только цветом |
| Замкнутость | Рамка = отдельный объект | Каждый слайд = `section.slide` с рамкой-фоном `#FAF6EE` |
| Фигура/фон | Главный объект выделяется | Бумага слайда светлее фона страницы, текст темнее фона |

## 0.6. Что запрещено с точки зрения нейробиологии

Эти решения вредят обучению. Если визуальный агент предложит их — это ошибка, а не «улучшение».

- ❌ Автопроигрывание анимаций (нарушает segmenting).
- ❌ Параллакс-эффекты (отвлекает от текста, требует рабочей памяти).
- ❌ Бесконечная лента без TOC (нарушает сегментацию).
- ❌ Иконки-эмодзи 🚨 💡 🛠️ (нарушает coherence, мешает signaling — все одного цвета).
- ❌ Текст на картинке (нарушает spatial contiguity — текст должен быть рядом, а не ВНУТРИ).
- ❌ Карусель картинок (нарушает temporal contiguity).
- ❌ Hover-эффекты со сменой цвета на всём абзаце (нарушает signaling — выделено должно быть только главное).

## 0.7. Как читать это ТЗ

Каждое решение в Частях 1–8 ссылается на принцип из Части 0. Например:

> *«figure.sketch width 50%»* — это реализация **Spatial Contiguity**.
> *«Три типа плашек»* — это реализация **Signaling**.
> *«Один слайд = одна мысль»* — это реализация **Chunking (Working Memory 4±1)**.

Если визуальный агент сомневается в решении — он открывает Часть 0 и находит принцип.

# ЧАСТЬ 1: ГЕОМЕТРИЯ — ГОРИЗОНТАЛЬНЫЙ СЛАЙД

## 1.1. Принцип

**Слайд = альбомная страница тетради.** Ширина больше высоты. Картинка слева занимает 50-55% ширины, текст справа — 45-50%. На одной странице помещается и **большая картинка (до 700px)**, и **полный текст абзаца без переноса**.

## 1.2. Размеры

| Параметр | Значение | Зачем |
|---|---|---|
| `main.content` max-width | **1400px** | Достаточно для картинки 700px + текст 600px |
| `section.slide` padding | **24px 36px** | Компактнее чем вертикальный (28px 32px), больше места под контент |
| `section.slide` margin-bottom | **24px** | Меньше воздуха между слайдами — горизонтально и так просторно |
| `figure.sketch` width | **50%** | Увеличено с 40% для большей картинки |
| `figure.sketch` max-width | **700px** | Абсолютный предел для очень широких экранов |
| Gap между картинкой и текстом | **36px** | Увеличено с 28px для лучшего визуального разделения |
| `main.content` padding | **28px 40px** | Чуть меньше вертикального |

## 2.4. Правило единое: ОБТЕКАЕТ ВСЁ

**Картинку обтекает всё:** текст абзацев, формулы KaTeX, таблицы, плашки, мини-тесты, `<details>`. Никаких исключений.

**Зачем:** одна мысль — один слайд — одна картинка; если на слайде есть и таблица, и плашка, и формула, и картинка — все они группируются вокруг рисунка, как блокнотные заметки вокруг эскиза. Не нужно решать «обтекать или нет» для каждого типа — все ведут себя одинаково.

```css
/* НЕ СТАВИМ clear:both ни на какие блоки внутри .slide-body */
/* Все элементы обтекают картинку (float:left у figure.sketch) */

/* Только clearfix для самого слайда — чтобы контейнер не схлопнулся */
.slide-body::after { content: ""; display: table; clear: both; }

/* Таблица — на всю оставшуюся ширину справа от картинки */
.slide-body table { width: auto; max-width: 100%; border-collapse: collapse;
                    margin: 0 0 12px; }
.slide-body th, .slide-body td { border: 1px solid #6E554F;
                                  padding: 6px 10px; vertical-align: top; }

/* Плашки и мини-тесты — на всю оставшуюся ширину */
.slide-body .note-trap, .slide-body .note-rule, .slide-body .note-cheat {
  display: block; width: auto; box-sizing: border-box;
  margin: 12px 0; padding: 12px 18px; background: #F3EBE3;
  border-left: 3px solid; border-radius: 4px; }
.slide-body .note-trap  { border-left-color: #D97443; }
.slide-body .note-rule  { border-left-color: #D1A153; }
.slide-body .note-cheat { border-left-color: #618B8B; }

/* Формула display-mode — обтекает, но если не помещается справа — уходит вниз */
.slide-body .katex-display { margin: 12px 0; }
```

**Что это меняет визуально:**
- Таблица рядом с картинкой становится «правым столбцом» (а не уезжает вниз).
- Плашка-ловушка «обнимает» картинку — заметнее.
- Если формула длиннее, чем помещается справа от 700px картинки — браузер сам перенесёт её вниз (это нормально).

**Исключение для титульника и финала:** `figure.sketch-full` — на всю ширину, без обтекания (там картинка сама по себе, не иллюстрация к тексту).

## 2.6. Качество и читабельность картинок

**Источники у нас хорошие** — но при вёрстке важно не испортить. Ниже — минимальные требования, чтобы при увеличении до 700px на retina display картинка оставалась чёткой.

### 2.5.1. Минимальное разрешение исходника

| Слот | Минимальная ширина PNG | Почему |
|---|---|---|
| `figure.sketch` (десктоп, 700px) | **1400px** в исходнике | Для retina display (`@2x`) — иначе мыло |
| `figure.sketch` (мобильный, 100%) | **600px** в исходнике | На телефоне хватает |
| `figure.sketch-full` (титул/финал, 100% main) | **1400px** в исходнике | Полная ширина — то же правило |
| Мелкие иконки-плашки в строке | **48px** | Не увеличивать |

**Что делать, если исходник меньше нужного:**
- ❌ НЕ увеличивать через CSS `transform: scale()` или `width` — будет мыло.
- ✅ Центрировать в слоте с сохранением пропорций (`max-width: 100%; height: auto;`).
- ✅ Сообщить Olga: «картинка X имеет Y×Z, для retina нужно W×H».

### 2.5.2. Формат файлов

| Использовать | Когда |
|---|---|
| **PNG** | Скриншоты, рукописные пометки, схемы со стрелками, формулы от руки (как наши) |
| **SVG** | Геометрические схемы, диаграммы (если появятся) — масштабируется без потерь |
| **WebP** | Фотографии (если появятся) — меньше размер, хорошее качество |
| ❌ JPG | Не использовать: артефакты сжатия на тонких линиях |

### 2.5.3. Контраст и читабельность линий

- **Линии на картинках** — минимум `#3E2723` (основной текстовый цвет), лучше `#2B2B2A`. Светло-серые линии `#999999` и тоньше — сливаются с кремовым фоном.
- **Подписи на картинках** — не мельче 14px в исходнике (иначе на 700px не читаются).
- **Фон внутри картинки** — если есть белый `#FFFFFF` внутри, проверить на контрасте с кремовым `#F5F2EB`. Если сливается — добавить тонкую рамку `1px solid #6E554F` вокруг `<figure>`.
- **Стрелки/указатели** — толщина линии ≥ 2px в исходнике.

### 2.5.4. Retina display

Современные экраны (MacBook, iPhone, iPad, многие ноутбуки) имеют `@2x`. Если вставить картинку 700×500 в слот 700×500, на retina будет мыло.

**Решение:** отдавать `@2x` версии рядом с обычными.

```html
<!-- Вариант 1: одна картинка высокого разрешения (простое решение, чуть больше размер файла) -->
<img src="assets/metricheskiy-most.png" alt="Метрический мост"
     style="width: 100%; height: auto;">

<!-- Вариант 2: srcset для оптимизации (если @2x версия есть отдельным файлом) -->
<img src="assets/metricheskiy-most.png"
     srcset="assets/metricheskiy-most.png 1x, assets/metricheskiy-most@2x.png 2x"
     alt="Метрический мост" style="width: 100%; height: auto;">
```

**По умолчанию:** Вариант 1 (один файл высокого разрешения ≥ 1400px шириной). Проще для пилота.

### 2.5.5. Подпись под картинкой (`figcaption`)

- **Шрифт:** Montserrat Regular, 12px, цвет `#6E554F`.
- **Расположение:** сразу под картинкой, центрировано или слева.
- **Содержание:** короткое (1 строка, до 60 символов). Не дублировать текст абзаца.
- **Запрещено:** эмодзи в подписи, длинные пояснения (для длинных — отдельный абзац).

### 2.5.6. Чек-лист качества перед сдачей

Визуальный агент ОБЯЗАН проверить:
- [ ] Каждая картинка открывается и читается на ширине 700px в Chrome DevTools с `@2x`.
- [ ] Линии не сливаются с кремовым фоном.
- [ ] Подписи под картинками читаются (12px, цвет `#6E554F`).
- [ ] Нет битых ссылок (`<img>` с `alt` но без `src` — ошибка).
- [ ] Соотношение сторон картинки не нарушено (`width: 100%; height: auto;`).
