# Дополнение к ТЗ: визуальный финальный проход v1.4

Файл дополняет `_TZ_верстка_читалка_sketchbook_ГОРИЗОНТАЛЬНАЯ.md` и фиксирует инсайты, которые появились в ходе живой вёрстки.

Главная идея: **каркас и текст — отдельно, смысловой визуал — отдельным финальным проходом**. Агент не должен «украшать» страницу автоматически. Он должен расставлять визуал как режиссёр учебного внимания.

---

## 1. Трёхэтапный контракт вместо двухэтапного

В базовом ТЗ уже есть два этапа:

1. каркас;
2. вставка картинок по реестру.

Добавляется третий этап.

### Этап 3. Смысловая режиссура визуала

**Когда выполняется:** только после того, как Olga подтвердила, что:

- каркас не едет;
- основные учебные картинки стоят;
- мини-тесты и ответы работают;
- TOC и scroll-spy в порядке.

**Что делает агент:**

1. Проходит все 58 секций.
2. Строит визуальную карту:

```text
slide-id | тип слайда | есть ли учебная картинка | есть ли мини-тест | есть ли плашка-ловушка | нужен ли стикер | кандидат визуала
```

3. Делит визуал на 4 категории:
   - учебная картинка;
   - картинка мини-теста;
   - смысловой стикер;
   - исключение, привязанное к конкретной плашке.
4. Предлагает Olga список решений перед массовой вставкой:

```text
Слайды без визуала: 9.5, 21.5, 22.11, 22.13.
Предлагаю:
9.5 — naity_celoe_procent.png / или podskazka.png
21.5 — chit-kod.png
22.11 — ty-smozhesh.png
22.13 — zapomni.png
Подтвердить?
```

5. После подтверждения вставляет визуал.
6. Делает ревью на перегруз:
   - нет ли рядом большой картинки и лишних стикеров;
   - не поехали ли формулы;
   - не возникли ли пустые дыры;
   - не стало ли больше одного смыслового акцента в одном месте.

**Почему так:** финальный визуал зависит от фактического набора картинок в `assets/`, от качества конкретных файлов и от вкусового решения Olga. Его нельзя идеально прописать заранее.

## 2. Закон визуальной иерархии

На слайде должен быть **один главный визуальный объект**.

### Приоритет визуалов

| Приоритет | Тип визуала | Пример | Правило |
|---:|---|---|---|
| 1 | Учебная картинка | `izmenenie-cen.png` | Главный объект слайда. Если она есть — стикеры обычно не нужны. |
| 2 | Картинка мини-теста | `game-3.png` | Главный объект мини-теста. Стикеры рядом не ставить. |
| 3 | Смысловой стикер | `zapomni.png`, `mostik.png` | Только если слайд текстовый и без большой картинки. |
| 4 | Исключение у плашки | `lovyushka-1.png` рядом с `.note-trap` | Только через специальный контейнер, не float. |

### Главное правило

Если на слайде уже есть полноценная учебная картинка — **не добавлять стикер**, чтобы не ломать обтекание и не перегружать рабочую память.

Исключение возможно только если стикер привязан к конкретной плашке через контейнер `.note-with-sticker`.

## 3. Учебные картинки

### 3.1. Обычная учебная картинка

- стоит слева;
- крупная;
- текст обтекает справа;
- используется для ключевого понятия, формулы, схемы, задачи;
- не конкурирует со стикерами.

```css
figure.sketch {
  float: left;
  width: 48-50%;
  max-width: 560-700px;
  margin-right: 1cm+;
}
```

### 3.2. Две учебные картинки на одном слайде

Разрешено только если без второй картинки смысл теряется.

Если две картинки перегружают слайд — вторую убрать.

**Зафиксированный пример:** слайд 5.  
Картинка определения `obratnaia-proporcia.png` остаётся. Картинку с малярами `obratnaya-zavisimost.png` убрать, потому что она дублирует смысл и перегружает слайд.

## 4. Мини-тесты

Мини-тесты — тёмные слайды. Значит, лучше использовать тёмные версии `game-*`.

### 4.1. Правило выбора

| Фон мини-теста | Визуал |
|---|---|
| Тёмный фон | тёмные/чёрные `game-*` |
| Светлый блок проверки | светлые `game-*`, если появятся |

### 4.2. Размер

Картинка мини-теста должна быть заметной и читабельной, но не как полноценная учебная иллюстрация.

Рекомендуемый слот:

```css
figure.mini-test-image {
  float: right;
  width: clamp(280px, 34%, 420px);
  max-width: 420px;
  min-width: 260px;
  border: 0;
  background: transparent;
  padding: 0;
}

figure.mini-test-image img {
  width: 100%;
  max-height: 360px;
  object-fit: contain;
}
```

### 4.3. Распределение

Не повторять один и тот же `game-*` везде. Подбирать по настроению блока.

Пример текущей логики:

```text
slide-3.5   → game-3.png
slide-5.5   → game-4.png
slide-8.5   → game-5.png
slide-11.5  → game-9.png
slide-12.5  → game-6.png
slide-14.5  → game-10.png
slide-16.5  → game-11.png
```

## 5. Стикеры

Стикеры — это не украшение, а сигнал внимания. Их нельзя расставлять автоматически «для красоты».

### 5.1. Когда стикер нужен

Стикер нужен, если слайд:

- текстовый;
- без полноценной картинки;
- содержит мостик, самопроверку, шпаргалку, глоссарий, карту пути;
- нуждается в эмоциональном/смысловом якоре.

### 5.2. Когда стикер НЕ нужен

Стикер не нужен, если:

- рядом уже стоит большая учебная картинка;
- рядом стоит картинка мини-теста;
- слайд и так визуально плотный;
- стикер повторяет смысл плашки, но не добавляет сигнал.

### 5.3. Один слайд — один стикер

По умолчанию на текстовом слайде максимум один стикер.

Если очень нужно два — они должны быть разведены по разным сторонам страницы. Но лучше избегать.

### 5.4. Стандартизация размера

Стикеры должны быть одинаковыми **по слоту**, а не обязательно по исходному файлу. Источники могут иметь разную прозрачную рамку и разные пропорции, поэтому визуальный агент должен стандартизировать контейнер.

Рекомендуемый слот:

```css
figure.inline-sticker {
  float: left;
  width: clamp(170px, 18%, 230px);
  max-width: 230px;
  min-width: 170px;
  border: 0;
  background: transparent;
  padding: 0;
}

figure.inline-sticker img {
  width: 100%;
  max-height: 190px;
  object-fit: contain;
}
```

Если PNG имеет слишком большие прозрачные поля, агент сообщает Olga:

```text
Стикер X визуально меньше остальных из-за прозрачных полей. Нужна обрезка alpha-bounds или замена.
```

### 5.5. Смысловая карта стикеров

| Смысл | Стикеры |
|---|---|
| Лайфхак | `layfkhak.png` |
| Самопроверка / скрипт | `klan-v-dele.png`, иногда `schitay.png` |
| Мостик | `mostik.png` |
| Ловушка | `lovyushka-1.png`, `lovyushka-2.png`, `vnimatelno.png`, `ne-razocharovyvay.png` |
| Алгоритм мышления | `kak-dumat.png` |
| Пример / решение | `primer.png`, `kak-naschet-uravneniya.png` |
| Шпаргалка / запомнить | `zapomni.png`, `chit-kod.png`, `podskazka.png` |
| Мотивация | `ty-smozhesh.png`, `hana-*` очень дозированно |

## 6. Исключения у плашек

Если стикер нужен рядом с конкретной плашкой, он не должен быть свободным float.

Использовать контейнер:

```html
<div class="note-with-sticker">
  <blockquote class="note-trap">...</blockquote>
  <figure class="inline-sticker sticker-exception">...</figure>
</div>
```

CSS:

```css
.note-with-sticker {
  clear: both;
  display: grid;
  grid-template-columns: minmax(0, 1fr) minmax(130px, 18%);
  column-gap: 24px;
  align-items: center;
  margin: 14px 0;
}

.note-with-sticker blockquote { margin: 0; }

.note-with-sticker figure.sticker-exception {
  float: none;
  width: 100%;
  max-width: 180-210px;
  min-width: 0;
  margin: 0;
  justify-self: end;
}
```

**Зафиксированный пример:** слайд 13, ловушка про старую/новую базу.

## 7. Финальные вопросы агента к Olga перед visual pass

Перед финальной расстановкой визуала агент должен задать короткий список вопросов, если есть неопределённость:

1. Какие новые картинки появились в `assets/` после прошлого прохода?
2. Какие картинки обязательны, даже если раньше были в списке «не вставлять»?
3. Какие слайды Olga считает визуально пустыми?
4. Где можно использовать `hana-*`, а где тон слишком жёсткий?
5. Разрешены ли исключения вида `.note-with-sticker` рядом с плашками?
6. Есть ли слайды, где картинку лучше убрать ради воздуха?

Агент не должен угадывать всё молча. Он может предложить карту визуала и попросить подтверждение.

## 8. Финальный QA «перфекто»

Перед сдачей агент проверяет:

- [ ] 58 секций на месте.
- [ ] Нет битых `src`.
- [ ] Нет слайдов с большой картинкой + лишними стикерами.
- [ ] Нет больше одного стикера на текстовом слайде.
- [ ] Исключения у плашек сделаны через `.note-with-sticker`, а не свободным float.
- [ ] Мини-тесты используют тёмные `game-*` на тёмном фоне.
- [ ] Стикеры стандартизированы по контейнеру.
- [ ] Картинки не мыльные и читаются.
- [ ] Нет «дыр» справа от картинки.
- [ ] Формулы не вылезают за карточку.
- [ ] Таблицы не ломают горизонтальную композицию.
- [ ] TOC ведёт на правильные id.
- [ ] Если менялась нумерация — обновлены id, TOC и ссылки.

## 10. Короткая формула всей работы

```text
Каркас → учебные картинки → смысловой visual pass → чистка перегруза → QA → фиксация ТЗ.
```

Главное: **лучше один сильный визуальный якорь, чем три милых стикера, которые ломают чтение.**

## 11. Ритм стикеров: не клеить всё в одну сторону

Стикеры на текстовых слайдах не должны монотонно стоять только слева или только справа. Это создаёт ощущение механической расклейки и перегружает один край страницы.

После визуальной гигиены применяется дополнительный проход:

1. На слайде остаётся максимум один обычный смысловой стикер.
2. Если рядом есть большая учебная картинка — обычный стикер удаляется.
3. Оставшиеся текстовые стикеры чередуются по стороне страницы:
   - первый — слева;
   - второй — справа;
   - третий — слева;
   - и так далее.
4. Исключения `.note-with-sticker` не участвуют в чередовании, потому что они привязаны к конкретной плашке.

CSS-опора:

```css
figure.inline-sticker { float: left; }
figure.inline-sticker.inline-sticker-right { float: right; }
```

Цель: сохранить живой скетчбук-ритм, но не возвращаться к хаосу и не ломать обтекание.

## 12. Дырявые vs плотные слайды

Не все слайды одинаковые по визуальной плотности. Есть:

- **плотные слайды** — много текста, формул, таблиц, уже есть большая учебная картинка;
- **дырявые слайды** — большой рисунок создаёт пустую правую зону, либо текстовый слайд выглядит слишком пусто.

### Правило

Сначала агент чистит перегруз. Потом делает отдельный проход на «дыры».

Если слайд плотный — ничего не добавлять.

Если слайд дырявый, можно добавить **один компактный filler-стикер**, но только если:

1. он не конкурирует с учебной картинкой;
2. он стоит в пустом месте, а не поверх логики текста;
3. он смысловой, а не декоративный;
4. он не входит в обычный rhythm-pass стикеров.

Пример CSS:

```css
figure.hole-filler-sticker {
  float: right;
  width: clamp(150px, 16%, 220px);
  max-width: 220px;
  min-width: 150px;
  border: 0;
  background: transparent;
  padding: 0;
}
```

Зафиксированный пример: слайд 12, где справа после таблицы переменных была пустая зона. Добавлен компактный `zapomni.png`, потому что смысл слайда — простой процент держит старую базу.

### Дополнение к правилу дырявых слайдов

Зафиксированные текущие примеры filler-визуала:

| Слайд | Что добавлено | Почему |
|---|---|---|
| 5 | `perevyortysh.png` как `hole-filler-sticker` | после удаления второй учебной картинки справа появилась пустота; стикер поддерживает тему обратности |
| 7 | `schitay.png` как `hole-filler-sticker` | слайд про переводы единиц просит визуальный счётный якорь |
| 12 | `zapomni.png` как `hole-filler-sticker` | простой процент держит старую базу |
| 13.2 | `lovyushka-2.png` через `.note-with-sticker` | ловушка «соль vs вода» должна быть привязана к плашке, а не свободно плавать |

## 13. Безопасная порядковая нумерация

Исходные номера слайдов могут быть не монотонными, потому что файл уже содержит внутреннюю учебную нумерацию: `9.1`, `12.5`, `15.6`, `21` перед `16` и т.д.

Чтобы не ломать ссылки внутри текста и не переименовывать все id, агент не обязан переписывать исходные номера. Вместо этого добавляется безопасный порядковый слой:

```html
<span class="order-num">№01</span>
<span class="slide-num">Слайд 0</span>
```

В TOC можно добавить `data-order="01"` для ссылок на секции:

```css
nav.toc a[data-order]::before {
  content: attr(data-order) " · ";
}
```

Так пользователь видит настоящий порядок чтения, а исходные `id` и ссылки в тексте остаются стабильными.

Полное переименование всех слайдов разрешено только отдельным явным решением Olga, потому что это затрагивает:

- `id` секций;
- ссылки TOC;
- ссылки внутри текста на «Слайд N»;
- старые заметки и комментарии по слайдам.
