# ТЗ MASTER — пушечная учебная читалка Sketchbook Horizontal

**Версия:** MASTER-Sketchbook-2.0  
**Назначение:** универсальное ТЗ на вёрстку любого нашего учебного продукта: математика, геометрия, проценты, алгебра, физика и т.д.  
**Формат результата:** длинная HTML-читалка с оглавлением, горизонтальными учебными карточками, крупным осмысленным визуалом и финальным visual-pass.  
**Главная цель:** сделать не просто красивый файл, а учебник, который читается, запоминается и не перегружает мозг.

---

## 0. Главная формула продукта

```text
Текст → каркас → учебные картинки → смысловой visual pass → чистка перегруза → QA → публикация
```

**Главный принцип:** лучше один сильный визуальный якорь, чем три милых стикера, которые ломают чтение.

---

# 1. Рабочий контракт

## 1.1. Текст заморожен

Агент не переписывает учебный текст без отдельного разрешения.

Разрешено без отдельного согласования:

- обернуть картинку в `<figure>`;
- вынуть `<img>` из `<p>`, если это нужно для вёрстки;
- завернуть ответы мини-тестов в `<details>`;
- классифицировать плашки;
- удалить мусорный одиночный символ/вариационный селектор;
- исправить чисто CSS/HTML-баги (`vertical-top` → `vertical-align: top`);
- добавить технические классы и контейнеры.

Запрещено без отдельного согласования:

- менять формулировки теории;
- переставлять слайды;
- выкидывать примеры;
- менять математический смысл;
- править таблицы как текст, если проблема не в вёрстке;
- менять нумерацию слайдов радикально, ломая id и ссылки.

---

## 1.2. Три этапа работы

### Этап 1. Каркас

Агент создаёт отдельный файл рядом с исходником:

```text
reader.html                 ← исходник не трогаем
reader-sketchbook.html      ← пробник / рабочий файл
assets/                     ← картинки
fonts/Montserrat/           ← локальный шрифт
```

Что делается:

- базовая сетка;
- TOC;
- цвета;
- шрифты;
- карточки-слайды;
- плашки;
- тёмные мини-тесты;
- `<details>` для ответов;
- scroll-spy;
- кнопка «Наверх»;
- адаптивность.

На этом этапе можно ставить плейсхолдеры, если картинки ещё не готовы.

---

### Этап 2. Учебные картинки

Агент вставляет полноценные учебные картинки:

```html
<figure class="sketch">
  <img src="assets/example.png" alt="...">
  <figcaption>...</figcaption>
</figure>
```

Правило:

- учебная картинка стоит слева;
- крупная;
- текст обтекает справа;
- расстояние от картинки до текста не меньше 1 см;
- подпись короткая и не дублирует абзац.

---

### Этап 3. Смысловая режиссура визуала

Это отдельный финальный проход. Он выполняется только после того, как каркас и основные картинки одобрены.

Агент строит карту визуала:

```text
slide-id | тип слайда | есть учебная картинка | есть мини-тест | есть ловушка | дырявый/плотный | кандидат визуала
```

Потом предлагает Olga решения:

```text
Слайды без визуала:
9.5, 21.5, 22.11, 22.13

Предлагаю:
9.5 — полноценная картинка
21.5 — chit-kod.png
22.11 — ty-smozhesh.png
22.13 — zapomni.png

Подтвердить?
```

Агент не должен угадывать всё молча, если решение спорное.

# 2. Нейробиологические основания

## 2.1. Рабочая память

Один слайд = одна мысль.

Нельзя класть на один слайд:

- много крупных картинок;
- много стикеров;
- несколько конкурирующих сигналов;
- таблицу, формулу, ловушку и три украшения одновременно.

Если слайд плотный — лучше оставить воздух.

---

## 2.2. Picture superiority

Картинка запоминается сильнее текста. Поэтому ключевые понятия получают визуальный якорь:

- теорема;
- определение;
- алгоритм;
- ловушка;
- схема;
- геометрическая конструкция;
- тип задачи.

Но картинка должна помогать учиться, а не просто украшать.

---

## 2.3. Spatial contiguity

Текст и картинка должны быть рядом.

Для наших продуктов:

```text
картинка слева → текст справа → всё в одном слайде
```

Если картинка относится к конкретной плашке, она должна быть физически привязана к этой плашке через контейнер, а не летать float-ом.

---

## 2.4. Coherence

Лишний визуал вредит.

Стикер нужен только если:

- он помогает понять смысл;
- закрывает визуальную дыру;
- сигналит важный тип блока;
- поддерживает эмоцию без перегруза.

---

# 3. Жанр страницы

Это **длинная учебная читалка-скетчбук**, не PPT и не Notion-карточки.

Визуальная метафора:

- кремовая бумага;
- чернила;
- карандашная учебная иллюстрация;
- горизонтальная карточка как разворот тетради;
- минимум цифровых эффектов.

# 7. Учебные картинки

## 7.1. Обычная учебная картинка

```css
figure.sketch {
  float:left;
  width:48-50%;
  max-width:560-700px;
  margin:0 1cm 0.6cm 0;
  border:1px solid #6E554F;
  background:#F5F2EB;
  padding:8px;
}

figure.sketch img {
  display:block;
  width:100%;
  height:auto;
  border:0;
  border-radius:0;
  box-shadow:none;
}
```

Правила:

- картинка слева;
- текст обтекает справа;
- gap не меньше 1 см;
- картинка крупная и читаемая;
- не вставлять картинку «ради картинки».

---

## 7.2. Две учебные картинки на одном слайде

Разрешено только если без второй картинки смысл теряется.

Если слайд перегружается — вторую картинку убрать.

Пример зафиксированного решения:

```text
Слайд 5: оставить картинку определения, убрать картинку с малярами.
```

---

## 7.3. Full image

Титул, финал, обложки:

```css
figure.sketch-full {
  float:none;
  width:100%;
  max-width:none;
}
```

# 9. Мини-тесты

Мини-тесты:

- тёмные слайды;
- ответы закрыты в `<details>`;
- 2 задачи, не 5;
- справа картинка `game-*`.

```css
figure.mini-test-image {
  float:right;
  width:clamp(280px, 34%, 420px);
  max-width:420px;
  min-width:260px;
  border:0;
  background:transparent;
  padding:0;
}
```

Правило выбора:

| Фон | Визуал |
|---|---|
| тёмный мини-тест | тёмные/чёрные `game-*` |
| светлый тестовый блок | светлые `game-*` |

# 10. Стикеры

Стикер — это сигнал, не украшение.

## 10.1. Когда стикер нужен

- слайд текстовый;
- нет большой картинки;
- есть мостик, самопроверка, шпаргалка, карта пути;
- нужна эмоция/сигнал.

## 10.2. Когда стикер не нужен

- уже есть большая учебная картинка;
- уже есть mini-test image;
- слайд плотный;
- стикер повторяет смысл, но не помогает.

## 10.3. Размер стикера

```css
figure.inline-sticker {
  float:left;
  width:clamp(170px, 18%, 230px);
  max-width:230px;
  min-width:170px;
  border:0;
  background:transparent;
  padding:0;
}

figure.inline-sticker img {
  width:100%;
  max-height:190px;
  object-fit:contain;
}
```

## 10.4. Ритм стикеров

Не клеить всё слева или всё справа.

После чистки визуала:

```text
1-й текстовый стикер — слева
2-й — справа
3-й — слева
4-й — справа
```

CSS:

```css
figure.inline-sticker.inline-sticker-right {
  float:right;
  margin-left:0.9cm;
}
```

# 12. Исключение: стикер у плашки

Если стикер нужен именно рядом с ловушкой/правилом, использовать контейнер:

```html
<div class="note-with-sticker">
  <blockquote class="note-trap">...</blockquote>
  <figure class="inline-sticker sticker-exception">...</figure>
</div>
```

```css
.note-with-sticker {
  clear:both;
  display:grid;
  grid-template-columns:minmax(0, 1fr) minmax(130px, 18%);
  column-gap:24px;
  align-items:center;
}
```

Нельзя ставить такой стикер свободным float-ом.

---

# 13. Дырявые и плотные слайды

## 13.1. Плотный слайд

Если слайд уже содержит:

- большую картинку;
- таблицу;
- несколько формул;
- длинный текст;
- плашку;

ничего не добавлять.

## 13.2. Дырявый слайд

Если справа визуальная пустота, можно добавить один компактный filler:

```css
figure.hole-filler-sticker {
  float:right;
  width:clamp(150px, 16%, 220px);
  max-width:220px;
  min-width:150px;
  border:0;
  background:transparent;
  padding:0;
}
```

Условия:

- filler смысловой;
- не конкурирует с учебной картинкой;
- стоит в пустой зоне;
- не ломает обтекание.

---

# 14. Нумерация

Исходные номера слайдов могут быть не монотонными.

Не переименовывать все id без отдельного разрешения.

Безопасное решение:

```html
<span class="order-num">№01</span>
<span class="slide-num">Слайд 0</span>
```

В TOC:

```css
nav.toc a[data-order]::before {
  content: attr(data-order) " · ";
}
```

Так пользователь видит настоящий порядок чтения, а исходные ссылки не ломаются.

---

# 15. TOC и навигация

TOC:

- слева;
- sticky;
- без синих ссылок;
- активный пункт мятный;
- block headers кликабельны;
- bridge headers кликабельны;
- scroll-spy через `IntersectionObserver`.

Кнопка «Наверх»:

```js
nav.toc.scrollIntoView({ behavior:'smooth' })
```

Не использовать `window.scrollTo(0,0)`.

---

# 16. KaTeX

Формулы остаются в HTML/KaTeX, не в картинках.

CDN можно оставить на пилоте. Для автономной публикации — локализовать KaTeX отдельным этапом.

На тёмном фоне формулы должны быть перекрашены в кремовый.

---

# 17. Производительность

Для всех картинок:

```html
<img loading="lazy" decoding="async" width="..." height="...">
```

Титульник:

```html
loading="eager"
```

Проверять тяжёлые картинки > 2 MB. Если картинка тяжелая, но нужна, можно оставить на пилоте, но отметить для оптимизации.

---

# 18. Адаптивность

На ширине ≤ 900px:

- TOC наверх;
- картинки перестают float-иться;
- текст идёт под картинкой;
- таблицы получают горизонтальный скролл;
- стикеры уменьшаются.

```css
@media (max-width:900px) {
  .layout { flex-direction:column; }
  nav.toc { width:100%; height:auto; position:relative; }
  figure.sketch { float:none; width:100%; max-width:560px; margin:0 auto 18px; }
  .slide-body table { display:block; overflow-x:auto; white-space:nowrap; }
}
```

# 19. Генерация нового визуала

Агент может генерировать простой визуал, если Olga разрешает.

Лучший prompt-канон:

```text
1024×1024, sketchbook educational illustration, cream paper background,
pencil and light watercolor, warm ink palette, one clear visual metaphor,
no Russian text inside image, no formulas inside image, no watermark,
clean composition, enough empty paper around central object
```

Не просить генератор писать точный русский текст или сложные формулы внутри картинки. Текст и формулы — в HTML.

# 20. Геометрия: отдельные правила

Для учебника по геометрии визуал особенно важен.

## 20.1. Что визуализировать обязательно

- определения фигур;
- теоремы;
- условия задач;
- построения;
- доказательства по шагам;
- типовые ошибки;
- связи между объектами.

## 20.2. Геометрические картинки

Предпочтительно:

- чистая схема;
- тонкие, но читаемые линии;
- точки и отрезки подписывать в HTML, если в картинке текст может исказиться;
- цветовые акценты использовать дозированно;
- если нужна точность — лучше SVG или ручная схема, а не генеративная картинка.

## 20.3. Доказательства

Доказательство лучше разбивать:

```text
картинка слева → шаг 1 справа → шаг 2 → формула → вывод
```

Если доказательство длинное, разбить на несколько слайдов.

# 21. Публикация

Для картинок нужны относительные пути:

```text
reader-sketchbook.html
assets/
fonts/
```

Если отправить только HTML без `assets`, картинки не появятся.

Для публичной ссылки:

- GitHub Pages;
- Netlify;
- Vercel;
- любой статический хостинг.

# 22. Финальный QA

Перед сдачей проверить:

- [ ] секции на месте;
- [ ] порядок секций сохранён;
- [ ] нет missing assets;
- [ ] у всех img есть `alt`, `width`, `height`, `loading`;
- [ ] нет синего `#2b6cb0`;
- [ ] нет `#FFFFFF` карточек;
- [ ] нет box-shadow;
- [ ] нет linear-gradient;
- [ ] нет drop-shadow;
- [ ] нет scale hover;
- [ ] нет `vertical-top`;
- [ ] мини-тесты тёмные;
- [ ] ответы закрыты;
- [ ] нет больших картинок + лишних стикеров;
- [ ] нет больше одного обычного стикера на текстовом слайде;
- [ ] исключения у плашек через `.note-with-sticker`;
- [ ] дырявые слайды закрыты аккуратным filler;
- [ ] плотные слайды не перегружены;
- [ ] TOC работает;
- [ ] scroll-spy работает;
- [ ] мобильная ширина не ломается.

# 23. Формат отчёта агента

После прохода агент пишет коротко:

```text
Сделано:
- слайд X: добавлена картинка ...;
- слайд Y: убран лишний стикер;
- мини-тесты: расставлены тёмные game-*;
- дырявые слайды: закрыты filler-стикерами.

Проверка:
- секций: N;
- missing assets: 0;
- big visual + sticker conflict: 0;
- details: N;
- запрещённые цвета/эффекты: 0.

Нужно решение Olga:
- оставить картинку ... или заменить?
```

# 24. Итоговое правило

```text
Учебник должен выглядеть как умная тетрадь:
крупный понятный рисунок + спокойный текст + точный сигнал внимания.
```

Не украшать. Режиссировать внимание.
